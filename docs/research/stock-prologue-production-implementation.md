# Prologue production implementation

This batch extends the first production D0 class with SystemV i64 functions containing the ordinary two-block frontend nop/jump/nop prologue and returning their sole parameter. The input predicate is structural; names, run metadata and values are arbitrary. Every D0 class is preserved. The existing theorem variants, input checks, allocator/settings, source/oracle indices, aliases and successful verification stages remain available.

The compiler and linker attempt the actual Stock path and retry the retained compiler after any pipeline/emission/layout error. The linker retains the original legacy layout on retry; `ProductionCompiler.accepts_legacy` proves the combined compiler accepts every successful legacy result. Runtime inputs contain data and routing metadata only. Fixed Lean proofs establish actual-output preparation, program correctness, image construction and concrete instruction execution, including original-source and peak-depth variants. Old APIs and theorem variants remain unchanged.

Default activation in this batch covers unoptimized programs without exceptional edges. Optimizer and unwind consumers retain their existing routes until their Stock adapters are proved; accepted programs remain accepted. Other source functions use the retained D0/legacy route. All remaining original #140 rule/effect/whole-driver simulation and completeness obligations remain open.

Targeted gates passed: proper source/consumer/compiler/CLI builds; 233 new consumer/compiler public roots plus the 46 preceding binary/prologue roots, standard-only; 1,441 owned constants standard-only across seven partitions; one MCP check of the original-source peak executable root (standard three, no warnings). The complete boundary witness adds 16 roots, nine explicitly marked as depending on fixed native compiler data. It constructs valid ABI/memory/stack/loader/source entries and proves executable refinement for every 64-bit argument in both modes, with actual non-legacy Stock history.

Eight actual linked cases and fourteen generated Lean files pass, including Stock prologues linked with a retained legacy caller in both modes, strict/fallback inputs, nonzero source/oracle indices and 33-function slicing. Real verified linker/checker CLIs selected the new path in both modes and compiled their two generated proof files. Runtime injection forces the first allocation attempt to fail and confirms exactly one successful legacy retry with identical retained output/stages. Early fixture-only failures (missing frontend declaration-table metadata) were fixed; their logs are retained.

Full per-PR scheduler, runtime/encoding, E2E identity/stage, linking, all trust audits and verified default Lean-linked crate gates remain to run on the frozen source before author squash.
